# xent-docs

The manual for Project Xent. Tutorials, concepts, and the quick start live
here as reStructuredText. The C API reference is generated by
[Hawkmoth](https://hawkmoth.readthedocs.io/) from the `/** */` comments on
public declarations in the sibling repositories.

A comment earns its place when the signature cannot carry the fact: ownership,
NULL, threading, callback lifetime, or failure. Hawkmoth prints that sentence
next to the declaration Clang already parsed. Parameter and return tags that
restate the signature are not used.

## Layout

This repository expects the code checkouts as siblings:

```
Xent/
  xent-docs/
  xent-core/
  xent-kit/
  fluxent/
  cwinrt/
```

Hawkmoth reads those trees. It does not vendor the headers.

## Build

```sh
py -3 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\sphinx-build -b html source _build/html
```

On Unix, use `python3 -m venv .venv` and `.venv/bin/sphinx-build`.

### Translations (`sphinx-intl`)

English in `source/*.rst` is the primary source. Simplified Chinese (`zh_CN`)
catalogs live under `source/locale/zh_CN/LC_MESSAGES/`:

```sh
.venv\Scripts\sphinx-build -b gettext source _build/gettext
.venv\Scripts\sphinx-intl update -p _build/gettext -l zh_CN
.venv\Scripts\sphinx-build -b html -D language=zh_CN source _build/html/zh_CN
```

`source/api/core.rst` and `source/api/kit.rst` parse portable C headers.
`source/api/fluxent.rst` also parses `<windows.h>`. On Windows the build
uses `C:\Program Files\LLVM\bin\clang.exe` when it is present, because that
Clang's default target is the Windows SDK. A MinGW `clang` on `PATH` is not
enough for that page.

Generated catalogs are left out: `xtk_controls.h`, and cwinrt's `Windows.*.h`.
The hand-written cwinrt runtime headers are documented in their own repository.
