4. 虚拟化列表、网格、树视图与子树缓存¶

Xent 的集合控件开箱支持视口虚拟化：无论数据集包含 50 条还是 10 万条记录，宿主始终只为当前可见窗口实例化控件，并在滚动时平滑复用行槽位。

虚拟化 ListView 、 ListBox 与 GridView¶

xtk_list （ &flux_ctrl_list ）、 xtk_listbox 、 xtk_gridview 与 xtk_repeater 共用 XtkListDesc 描述结构。只需提供总条数 .nitem 与按需构建函数 item(ui, env, index) ，宿主便会自动构建可见视口内的行：

static XtkEl *build_contact_row(XtkUi *ui, void *env, int index) {
    Model const *m = env;
    return xtk_row(
        ui, (XtkStackDesc) {.gap = 12, .align = XENT_FLEX_ALIGN_CENTER},
        xtk_kids(
            xtk_sized(xtk_text(ui, xtk_fmt(ui, "#%d", index), (XtkTextDesc) {.size = 12}), 64.0f, NAN),
            xtk_text(ui, xtk_fmt(ui, "Record %d (filter: %d)", index, m->active_filter), (XtkTextDesc) {0})
        )
    );
}

// Inside view():
xtk_grow(
    xtk_list(ui, (XtkListDesc) {
        .nitem                = 100000,
        .itemh                = 40.0f,
        .item                 = build_contact_row,
        .env                  = (void *) m,
        .sel_mode             = XTK_LIST_SELECT_SINGLE,
        .sel                  = m->selected_row,
        .select               = xtk_msg(MSG_ROW_SELECT),
        .item_invoked_enabled = true,
        .invoke               = xtk_msg(MSG_ROW_ACTIVATE),
    }),
    1.0f
)

固定行高与可变行高测量¶

  • 统一固定行高 ：将 .itemh 设为 40.0f （或所需像素高度），可实现 O(1) 精确滚动条定位。

  • 动态测量可变行高（0.3.3 默认行为） ：当各行包含多行折行文本或不等高内容时，保持 .itemh = 0 ，Fluxent 会自动测量已实例化行的真实高度，并根据滑动平均值估算视口外总高度。

选择模式与矩形框选（Rubber-Band）¶

通过 .sel_mode 选择交互模式：

  • XTK_LIST_SELECT_SINGLE —— 单选模式，通过 .sel 与 msg.i 同步选中下标。

  • XTK_LIST_SELECT_NONE —— 纯展示或仅响应行激活（invoke）的列表。

  • XTK_LIST_SELECT_MULTIPLE —— 多选复选框模式，点击逐行切换勾选。

  • XTK_LIST_SELECT_EXTENDED —— 资源管理器式扩展多选，支持 Ctrl+单击 、 Shift+单击 连续区间与 Ctrl+A 全选；在 0.3.3 中设置 .rect_select = true 可进一步启用鼠标拖拽橡皮筋矩形框选。

网格布局与 ItemsView¶

多列磁贴网格可使用 xtk_gridview 配合 .itemw 与 .itemh （ .ncol = 0 时按容器宽度自动计算列数），或使用 xtk_itemsview （ &flux_ctrl_itemsview ）配合 XTK_ITEMS_LAYOUT_UNIFORM_GRID / XTK_ITEMS_LAYOUT_FLOW 。

带吸顶标题的分组列表（0.3.3）¶

xtk_list 与 xtk_gridview 均支持分段数据与 WinUI 风格的内联吸顶组标题。在 .groups 中传入各组元素个数的 int32_t 数组、在 .ngroup 中指定组数，并提供 .group_header 构建函数：

static int32_t const kSectionCounts[3] = { 4, 12, 7 }; // Total .nitem = 23

static XtkEl *build_section_header(XtkUi *ui, void *env, int group) {
    (void) env;
    static char const *const kTitles[3] = { "Pinned", "Recent", "Archived" };
    return xtk_text(ui, kTitles[group], (XtkTextDesc) {.size = 18, .weight = XTK_FONT_SEMI_BOLD});
}

xtk_list(ui, (XtkListDesc) {
    .nitem        = 23,
    .itemh        = 40.0f,
    .groups       = kSectionCounts,
    .ngroup       = 3,
    .group_header = build_section_header,
    .item         = build_contact_row,
    .env          = (void *) m,
    .sel_mode     = XTK_LIST_SELECT_SINGLE,
    .sel          = m->selected_row,
    .select       = xtk_msg(MSG_ROW_SELECT),
})

注意 item(ui, env, index) 接收的依然是 0 .. nitem - 1 的逻辑数据下标，而 group_header 接收 0 .. ngroup - 1 的组下标。如需将组头与数据项交错排列的扁平行号映射回 {group, item} ，可调用 xtk_list_row(groups, ngroup, flat_row) 。

带 ColumnHeader 表头的明细列表（0.3.3）¶

将 xtk_colheader （需注册 &flux_ctrl_colheader 与 &flux_ctrl_colitem ）挂载到 XtkListDesc.header 上，即可构建支持点击排序箭头、拖拽调整列宽、双击分隔线自适应列宽以及拖拽重排列顺序的明细表格：

XtkEl *hdr = xtk_colheader(ui, xtk_kids(
    xtk_colitem(ui, "Name", (XtkColItemDesc) {
        .width   = m->col_w[0],
        .min_width = 120.0f,
        .sort    = m->sort_col == 0 ? (m->sort_desc ? XTK_SORT_DESCENDING : XTK_SORT_ASCENDING) : XTK_SORT_NONE,
        .click   = xtk_msg_i(MSG_COL_SORT, 0),
        .resize  = xtk_msg_i(MSG_COL_RESIZE, 0),
        .fit     = xtk_msg_i(MSG_COL_FIT, 0),
        .reorder = xtk_msg_i(MSG_COL_REORDER, 0),
    }),
    xtk_colitem(ui, "Size", (XtkColItemDesc) {
        .width   = m->col_w[1],
        .align   = XTK_ALIGN_RIGHT,
        .click   = xtk_msg_i(MSG_COL_SORT, 1),
        .resize  = xtk_msg_i(MSG_COL_RESIZE, 1),
    })
));

// Pass .header = hdr on XtkListDesc, and size cells in each row to m->col_w[c].

在 update() 中， .resize 将调整后的列宽写入 msg.f （列下标在 msg.i 中）， .reorder 将目标位置放入 msg.i 、被拖动的原列放入 (int) msg.d 。

层级树视图 TreeView¶

xtk_tree （ &flux_ctrl_tree ）将 XtkTreeNodeDesc 层级树中的可见节点展平为带展开/折叠箭头的虚拟化列表：

static XtkTreeNodeDesc const kSrcFiles[] = {
    {.text = "main.c", .icon = "Document"},
    {.text = "view.c", .icon = "Document"},
};

XtkTreeNodeDesc roots[] = {
    {
        .text        = "src",
        .icon        = "Folder",
        .expanded    = m->src_expanded,
        .children    = kSrcFiles,
        .child_count = 2,
    },
    {.text = "xmake.lua", .icon = "Document"},
};

xtk_sized(
    xtk_tree(ui, (XtkTreeDesc) {
        .roots    = roots,
        .nroot    = 2,
        .sel_mode = XTK_TREE_SELECT_SINGLE,
        .sel      = m->tree_sel,
        .select   = xtk_msg(MSG_TREE_SELECT),
        .expand   = xtk_msg(MSG_TREE_EXPAND),
        .invoke   = xtk_msg(MSG_TREE_INVOKE),
    }),
    NAN, 280.0f
)

.select 、 .expand 与 .invoke 均在 msg.i 中报告 当前可见行的扁平下标 ； .expand 同时在 msg.b 中给出新的展开布尔值。

协调器节点键（Key）与缓存区域¶

使用 xtk_keyed_u64 与 xtk_keyed 保持节点身份¶

容器内的同级元素默认按位置匹配。当子元素会发生排序变化、中间增删，或在同一个父槽位下切换不同页面时，为其指定稳定键值即可让保留状态（滚动偏移、焦点、过渡动画、输入光标）始终跟随对应的逻辑条目：

  • xtk_keyed_u64(el, item_id) —— 零内存分配的 64 位整数键（推荐用于记录 ID、页面枚举 ID 与标签页 ID）。

  • xtk_keyed(ui, xtk_fmt(ui, "card-%s", slug), el) —— 字符串键（便于命名路由与调试诊断）。

利用静态与记忆化区域跳过未变子树¶

当界面中既有高频刷新的状态指示器，又有很少改动的复杂侧边栏或大型表单时，可通过区域缓存直接跳过未变子树的构建与比对：

  • xtk_static_region(ui, 0x1001u, build_footer, NULL) —— 首帧调用一次 build_footer ，后续所有帧直接复用保留子树。

  • xtk_memo_region(ui, 0x1002u, m->sidebar_rev, build_sidebar, (void *) m) —— 仅当 m->sidebar_rev 变化时重建该子树；只需在 update() 中真正修改侧边栏数据的分支里递增 m->sidebar_rev 。
