1. Elm MVU 循环与应用结构¶

每一个 Xent 声明式程序都遵循源于 Elm 的 Model–View–Update（MVU） 架构。理清一帧之内数据、消息与帧内存池的流向，就能以一致的方式驾驭 <xtk/xtk.h> 中的所有控件。

单向帧循环¶

     ┌──────────────────────────────────────────┐
     │                                          ▼
┌─────────┐    view(ui, model)    ┌──────────────────────────┐
│  Model  │ ────────────────────► │  Transient Element Tree  │
└─────────┘                       └──────────────────────────┘
     ▲                                          │
     │ update(model, msg)                       │ User clicks / edits
     │                                          ▼
┌─────────┐                             ┌──────────────┐
│ XtkMsg  │ ◄────────────────────────── │ Retained UI  │
└─────────┘                             └──────────────┘

  1. Model（状态模型） ：一个普通的 C struct ，集中保存应用的全部状态——当前页面索引、表单文本、选中项下标、对话框开关标志以及已加载的业务数据。

  2. View（视图函数 XtkEl *view(XtkUi *ui, void *model) ） ：读取 Model 并返回在 ui 帧内存池中分配的轻量 XtkEl * 描述树。交互控件携带 XtkMsg 消息值，用于表达触发时发生了什么动作。

  3. Update（更新函数 void update(void *model, XtkMsg msg) ） ：当用户点击按钮、编辑文本或滚动列表时，宿主会将该控件绑定的 XtkMsg 放入队列。在构建下一帧前，运行时依次将队列中的消息交给 update() 处理，根据 msg.tag 就地修改 Model 。

  4. 协调与提交（Reconcile & Commit） ：消息队列清空后， flux_run 重置 XtkUi 帧内存池，调用一次 view() ，将新生成的元素树与上一帧结构比对，并向现有的 Windows 原生控件原子提交最小 XtkBatch 变更。

拆解 fluxent.decl 计数器模板¶

执行 xmake create -l c -t fluxent.decl hello 会在 src/main.c 中生成如下完整程序：

#include <fluxent/fluxent.h>
#include <fluxent/flux_app.h>

#include <math.h>

enum {
    MSG_INC = 1,
    MSG_DEC,
    MSG_RESET,
};

typedef struct Model {
    int n;
} Model;

static void update(void *model, XtkMsg msg) {
    Model *m = model;
    switch (msg.tag) {
    case MSG_INC   : m->n++; break;
    case MSG_DEC   : m->n--; break;
    case MSG_RESET : m->n = 0; break;
    default        : break;
    }
}

static XtkEl *view(XtkUi *ui, void *model) {
    Model const *m = model;
    return xtk_column(
        ui, (XtkStackDesc) {.gap = 16, .padding = {32, 32, 32, 32}, .align = XENT_FLEX_ALIGN_START},
        xtk_kids(
            xtk_text(ui, "Counter", (XtkTextDesc) {.size = 28, .weight = XTK_FONT_SEMI_BOLD}),
            xtk_text(ui, xtk_fmt(ui, "Value: %d", m->n), (XtkTextDesc) {.size = 20}),
            xtk_row(
                ui, (XtkStackDesc) {.gap = 8, .align = XENT_FLEX_ALIGN_CENTER},
                xtk_kids(
                    xtk_sized(xtk_button(ui, "−", (XtkButtonDesc) {.click = xtk_msg(MSG_DEC)}), 48, NAN),
                    xtk_sized(
                        xtk_button(ui, "+", (XtkButtonDesc) {.style = XTK_BUTTON_ACCENT, .click = xtk_msg(MSG_INC)}),
                        48, NAN
                    ),
                    xtk_button(ui, "Reset", (XtkButtonDesc) {.style = XTK_BUTTON_SUBTLE, .click = xtk_msg(MSG_RESET)})
                )
            )
        )
    );
}

int WINAPI WinMain(HINSTANCE hInst, HINSTANCE hPrev, LPSTR cmdLine, int showCmd) {
    (void) hInst; (void) hPrev; (void) cmdLine; (void) showCmd;

    flux_controls_use(&flux_ctrl_container);
    flux_controls_use(&flux_ctrl_text);
    flux_controls_use(&flux_ctrl_button);
    static Model model;
    return flux_run(
        &(FluxAppCfg) {.title = L"hello", .width = 480, .height = 320, .backdrop = FLUX_BACKDROP_MICA},
        &model, update, view
    );
}

设计 Model 与 XtkMsg¶

消息标签编号与附加参数¶

XtkMsg 是定义在 <xtk/xtk_msg.h> 中的普通值结构体：

typedef struct XtkMsg {
    int32_t tag;
    int32_t i;
    float   f;
    double  d;
    bool    b;
    void   *ptr;
} XtkMsg;

  • 枚举从 1 开始编号 ：零初始化的描述结构体字段（例如 (XtkButtonDesc) {.style = XTK_BUTTON_SUBTLE} 中未指定的 .click ）默认 tag == 0 ，表示该事件保持未绑定状态。

  • 用 xtk_msg_i 附带条目下标 ：当多个按钮共用同一类动作（如工具栏命令或动态生成的行按钮）时，绑定 xtk_msg_i(MSG_REMOVE_ITEM, row_index) 即可让 update() 同时收到 msg.tag 与 msg.i 。

用函数分发表扩展大型 update()¶

当应用的消息种类超过十余个时，可将各分支拆分为独立的小函数，并通过数组分发表索引（Fluxent 官方画廊与安装向导示例均采用这一结构）：

typedef void (*MsgHandlerFn)(Model *m, XtkMsg msg);

static void on_inc(Model *m, XtkMsg msg)   { (void) msg; m->n++; }
static void on_dec(Model *m, XtkMsg msg)   { (void) msg; m->n--; }
static void on_reset(Model *m, XtkMsg msg) { (void) msg; m->n = 0; }

static MsgHandlerFn const kHandlers[] = {
    [MSG_INC]   = on_inc,
    [MSG_DEC]   = on_dec,
    [MSG_RESET] = on_reset,
};

static void update(void *model, XtkMsg msg) {
    size_t count = sizeof(kHandlers) / sizeof(kHandlers[0]);
    if (msg.tag > 0 && (size_t) msg.tag < count && kHandlers[msg.tag]) {
        kHandlers[msg.tag]((Model *) model, msg);
    }
}

在 view() 中即时计算派生显示值¶

保持 Model 字段精简规范——只存储原始业务状态（如 file_done 与 file_count ），而在 view() 中即时计算格式化文本、进度百分比和按钮禁用条件。由于每次 Model 变化后都会运行 view() ，所有派生界面属性都会自动保持同步。

注册控件模块¶

在 Fluxent 0.3.3 中，各控件通过 <fluxent/flux_controls.h> 按需链接：

  • 正式发布构建 ：对视图用到的每类控件调用 flux_controls_use(&flux_ctrl_<name>) （例如 xtk_column / xtk_row 对应 &flux_ctrl_container ，以及 &flux_ctrl_text 、 &flux_ctrl_button ），未引用的控件实现会被链接器自动裁剪。

  • 快速原型阶段 ：启动时调用一次 flux_controls_all() 即可注册全部 70 余种内置控件，方便随时调整界面。

请在调用 flux_run 之前完成控件模块注册。

帧内存池（Scratch Arena）生命周期¶

XtkUi * 内置高速线性帧内存池，在每次 view() 开始时重置，并持续有效至当帧 XtkBatch 提交完成：

  • 动态文本 ：通过 xtk_fmt(ui, "Count: %d", m->n) 格式化字符串，或用 xtk_strdup(ui, temp) 拷贝临时缓冲区。字符串字面量（ "Reset" ）以及 Model 内部持有的持久字符串生命周期跨帧，可直接传入。

  • 动态子元素数组 ：在循环中生成可变数量的子元素时，从同一个帧内存池分配指针数组并以 XTK_END 结尾：

    XtkEl **items = xtk_children_alloc(ui, count + 1);
for (int i = 0; i < count; i++) {
    items[i] = xtk_text(ui, m->labels[i], (XtkTextDesc) {0});
}
items[count] = XTK_END;
return xtk_column(ui, (XtkStackDesc) {.gap = 8}, items);
