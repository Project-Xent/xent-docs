4. 事件路由、帧同步与变更戳¶

命令式 Xent 按捕获、目标、冒泡三阶段分发标准化 UI 事件，并让你完全掌控状态变更如何合并为界面更新。

订阅事件的三种方式¶

  1. 强类型事务订阅函数 （最常用）： <xtk/xtk_controls.h> 生成的 xtk_<ctrl>_on<event> 在事务构建期间默认监听 XTK_EVENT_PHASE_MASK_TARGET 阶段：

    xtk_button_oninvoke(&txn, xtk_ref_local(btn), on_save_clicked, app);
xtk_textbox_onchange(&txn, xtk_ref_local(box), on_name_edited, app);
xtk_slider_onchange(&txn, xtk_ref_local(sld), on_volume_changed, app);

  2. 指定传播阶段的事务订阅 ： xtk_txn_on 支持对任意 XtkEventId 选择 XTK_EVENT_PHASE_MASK_CAPTURE （从根向父节点下传）、 XTK_EVENT_PHASE_MASK_TARGET 、 XTK_EVENT_PHASE_MASK_BUBBLE （从父节点向根冒泡）或 XTK_EVENT_PHASE_MASK_ALL ：

    XtkSubRef sub = xtk_txn_on(
    &txn, xtk_ref_local(card),
    XTK_EVENT_INVOKE, XTK_EVENT_PHASE_MASK_BUBBLE,
    on_any_card_button, app
);

    若后续需要用 xtk_txn_off(&txn, sub_id) 动态取消订阅，可在提交后从 result->subscriptions 将 sub 映射为持久 XtkSubId 。

  3. 宿主级直接订阅 ： flux_host_subscribe 与 flux_host_unsubscribe 可在事务外直接对已提交的 XtkCtrl 增删监听器。

重要

宿主会持续借用传入的 void *arg （ userdata ）指针，直至该订阅被移除（调用 xtk_txn_off 、 flux_host_unsubscribe 或销毁目标控件所在子树）或 flux_host_destroy 执行完毕。请将 arg 保存在 App 结构体或页面级内存池中，在控件销毁提交后再释放。

解析 XtkEvent 与 XtkEventPayload¶

每个 XtkEventFn 回调都会收到 XtkEvent const *event ：

  • event->source / event->target / event->current_target —— 标识触发事件的源控件 XtkCtrl 以及当前正在执行回调的节点。

  • event->cause —— 区分事件触发来源： XTK_EVENT_CAUSE_USER 、 PROGRAM 、 BINDING 或 ACCESSIBILITY 。

  • event->payload —— 带标签联合体，按 event->payload.kind 读取对应成员：

event->payload.kind

联合体成员

典型事件

XTK_EVENT_PAYLOAD_NONE

（无载荷）

Button 点击激活、 PullToRefresh 下拉刷新触发

XTK_EVENT_PAYLOAD_BOOL

u.b

CheckBox / ToggleSwitch 切换、拖放悬停

XTK_EVENT_PAYLOAD_I32

u.i32

ComboBox / ListView / TabView / NavigationView 选中项、 ContentDialog 关闭结果

XTK_EVENT_PAYLOAD_F32

u.f32

Slider 数值变化、 ColumnHeader 列宽拖拽

XTK_EVENT_PAYLOAD_F64

u.f64

NumberBox / ScrollBar 数值变化

XTK_EVENT_PAYLOAD_STRING

u.string.{data, len}

TextBox / PasswordBox 编辑、拖入文件或文本（ 仅在回调执行期间有效 ——需保存时立即拷贝）

XTK_EVENT_PAYLOAD_QUERY

u.query.{text, len, index}

AutoSuggestBox 提交查询/选择建议项（ 在回调内拷贝 text ）

XTK_EVENT_PAYLOAD_INDEX_BOOL

u.index_bool.{index, value}

TreeView 节点展开/折叠、 CalendarView 日期点选

XTK_EVENT_PAYLOAD_RANGE

u.range.{start, end}

双滑块范围 Slider 变更

XTK_EVENT_PAYLOAD_WINDOW

u.window.{first, last, lanes}

虚拟化列表/网格上的 XTK_EVENT_REALIZE 视口范围事件

XTK_EVENT_PAYLOAD_SCROLL

u.scroll.{x, y, max_x, max_y}

ScrollViewer 视口滚动

事件处理完毕返回 XTK_EVENT_HANDLED ；如需停止向祖先节点冒泡可按位或上 XTK_EVENT_STOP_PROPAGATION 或 XTK_EVENT_STOP_IMMEDIATE ；返回 XTK_EVENT_CONTINUE （ 0 ）则继续常规路由。

按帧合并的 UI 同步模式¶

通过 flux_app_onframe 将业务状态更新与场景属性写入解耦，可以把单个垂直同步周期内的多次输入事件合并为一次干净的界面更新：

// 1. Event callbacks update C state, copy any borrowed strings, and schedule a frame:
static uint32_t on_name_change(void *arg, XtkEvent const *e) {
    App *app = arg;
    free(app->name);
    if (e->payload.kind == XTK_EVENT_PAYLOAD_STRING && e->payload.u.string.data) {
        uint32_t len = e->payload.u.string.len;
        app->name = malloc(len + 1);
        if (app->name) {
            memcpy(app->name, e->payload.u.string.data, len);
            app->name[len] = '\0';
        }
    } else {
        app->name = NULL;
    }
    app->dirty = true;
    flux_app_redraw(app->flux);
    return XTK_EVENT_HANDLED;
}

// 2. Once per frame before rendering, flush dirty state into retained controls:
static void on_frame(void *arg) {
    App *app = arg;
    if (!app->dirty) return;
    app->dirty = false;

    char greeting[128];
    int len = snprintf(greeting, sizeof(greeting), "Hello, %s!",
                       app->name && app->name[0] ? app->name : "stranger");
    xtk_text_settext(&app->scene, app->greeting_label, greeting, (uint32_t) len, (XtkChangeStamp) {0});
}

受控输入与 XtkChangeStamp 变更戳¶

所有属性写入函数都接收一个 XtkChangeStamp { XtkSourceId source; uint64_t revision; } 参数：

  • 对输出控件的程序写入或外部重置 ：传入 (XtkChangeStamp) {0} （即 source == 0 且 revision == 0 ）。这会直接覆盖控件属性值——适用于更新输出文本标签、切换按钮状态，或点击“重置”按钮清空 TextBox 。

  • 受控双向回显 ：用户在 TextBox 中输入时，触发的 XtkEvent 带有该控件生成的非零 event->change 变更戳。若架构在 on_frame 中把模型值统一回写给输入框，原样转发该 event->change 即可告知宿主本次回显对应的编辑版本，从而完好保留控件上更新的按键输入与正在进行的输入法组字。在纯命令式代码中，仅在外部动作（如“重置”按钮）时修改 TextBox 会让 on_name_change 更加直接，因为控件本身已经实时展示了用户的输入。
