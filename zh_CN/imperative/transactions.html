2. 原子事务与动态子树管理¶

保留式 XtkScene 的所有结构性变更——创建控件、销毁子树、插入、同级重排、跨父节点重挂载以及绑定事件监听——都在 <xtk/xtk_scene.h> 声明的 XtkTxn 事务中完成。

全有或全无的原子提交保证¶

调用 xtk_txn_commit(&txn, &diag) 时，宿主按四个阶段执行（ VALIDATE 、 PREFLIGHT 、 PREPARE 、 COMMIT ）：

  • 在触碰活动树之前，预先校验全部句柄代次、父子无环约束、已注册控件类型、属性类型及所需内存分配。

  • 校验与准备全部通过后，批次内的所有变更一次性生效，并推进 xtk_scene_revision(&scene) 版本号。

  • 若任意一步失败， xtk_txn_commit 返回 NULL 、填入可选的 XtkBatchDiag 诊断结构，并保持原有 XtkScene 完好不变。

事务操作函数一览¶

函数

用途

xtk_txn_begin(&scene, &txn)

开启一个由新 XtkBatch 承载的事务。

xtk_<ctrl>_create(&txn, parent, &props)

<xtk/xtk_controls.h> 中的强类型创建函数；将新控件追加到 parent 末尾并返回 XtkLocalId 。

xtk_txn_create(&txn, type, parent, before, patches, count)

面向任意 XtkCtrlId （如 XTK_CTRL_LISTITEM 或 XTK_CTRL_GROUPHEADER ）的底层创建函数，支持指定 before 插入位置。

xtk_txn_insert(&txn, parent, child, before)

将尚无父节点的控件插入到 before 之前（ before 为 xtk_ref_none() 时追加到末尾）。

xtk_txn_move(&txn, parent, child, before)

在当前同一个 parent 下调整 child 的同级排列顺序。

xtk_txn_reparent(&txn, child, new_parent, before)

将已有父节点的 child 迁移至新的父节点 new_parent 下。

xtk_txn_drop(&txn, target)

销毁 target 及其全部后代子树，自动解除其上的事件订阅并使旧 XtkCtrl 代次失效。

xtk_txn_commit(&txn, &diag)

原子提交整个批次并返回堆分配的 XtkBatchResult * （出错时返回 NULL ）。

xtk_txn_abort(&txn)

放弃尚未提交的事务并释放其内部批次缓冲区。

使用 XtkNodeRef 统一寻址节点¶

在未提交的 XtkTxn 中，往往需要同时引用先前已提交的持久控件（如 xtk_scene_root(&scene) ）和前两行刚创建、仅有批次局部编号 XtkLocalId 的新控件。 XtkNodeRef 统一表示这三类引用：

  • xtk_ref_existing(ctrl) —— 包装先前批次已提交的带代次校验 XtkCtrl 句柄。

  • xtk_ref_local(local_id) —— 包装 当前 XtkTxn 中刚创建的 XtkLocalId 。

  • xtk_ref_none() —— 空节点引用（作为 before 参数时表示追加到子列表末尾）。

提交后将 XtkLocalId 解析为持久 XtkCtrl¶

静态标题、布局容器与分隔线在挂载完子节点后通常无需再次修改，其 XtkLocalId 用完即可忽略。对于后续需要动态更新属性的控件，可从 XtkBatchResult 中提取持久 XtkCtrl 句柄：

static XtkCtrl resolve_ctrl(XtkBatchResult const *res, XtkLocalId local) {
    if (local == XTK_LOCAL_INVALID) return XTK_CTRL_INVALID;
    for (uint32_t i = 0; i < res->control_count; i++) {
        if (res->controls[i].local == local) {
            return res->controls[i].control;
        }
    }
    return XTK_CTRL_INVALID;
}

读取完 result->controls 与 result->subscriptions 后，调用 xtk_batchresult_destroy(result) 释放非空的 XtkBatchResult * 。

使用 XtkBatchDiag 排查批次失败原因¶

开发阶段向 xtk_txn_commit 传入 XtkBatchDiag ，可在批次被拒绝时直接定位失败的操作序号与错误码：

XtkBatchDiag    diag   = {0};
XtkBatchResult *result = xtk_txn_commit(&txn, &diag);
if (!result) {
    fprintf(stderr, "Batch failed: error=%d stage=%d op=%u\n",
            (int) diag.error, (int) diag.stage, diag.failed_op);
    return false;
}

常见 diag.error 原因：

  • XTK_BATCH_ERR_BACKEND —— 启动时漏掉了该控件对应的 flux_controls_use 模块注册。

  • XTK_BATCH_ERR_UNKNOWN_CONTROL / STALE_HANDLE —— 传入的 XtkCtrl 句柄所属子树已在之前的批次中被销毁。

无闪烁原子切页模式¶

在多视图命令式应用中切换页面（如响应 NavigationView 或 TabView 选择事件）时，在 同一个 XtkTxn 内销毁旧页面根节点并构建新页面子树：

static bool switch_page(App *app, int next_page) {
    XtkTxn txn;
    if (!xtk_txn_begin(&app->scene, &txn)) return false;

    // 1. Drop the previous page subtree in the same transaction
    if (app->page_root != XTK_CTRL_INVALID) {
        xtk_txn_drop(&txn, xtk_ref_existing(app->page_root));
    }

    // 2. Build the new page under the persistent NavigationView handle
    XtkLocalId scroll = xtk_scroll_create(
        &txn, xtk_ref_existing(app->nav_ctrl),
        &(XtkScrollProps) {.set = XTK_SCROLL_GROW_MASK, .grow = 1.0f}
    );
    build_page_contents(app, &txn, xtk_ref_local(scroll), next_page);

    // 3. Commit both the drop and the new build atomically—zero flicker
    XtkBatchResult *res = xtk_txn_commit(&txn, NULL);
    if (!res) return false;

    // 4. Now that old subscriptions are detached, free old page callback contexts
    free_previous_page_contexts(app);
    app->page_root = resolve_ctrl(res, scroll);
    xtk_batchresult_destroy(res);
    return true;
}

在包含 xtk_txn_drop 的事务成功提交 之后 再释放旧页面事件回调所借用的 userdata 内存，可确保控件存活期间所有借用指针始终有效。
